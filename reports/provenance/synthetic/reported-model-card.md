# City Sample Vehicle Keypoints - 24-point (synthetic-only)

A YOLO-pose model trained **entirely on synthetic data** - the
[City Sample 24-point vehicle-keypoint dataset](https://huggingface.co/datasets/kiselyovd/citysample-vehicle-keypoints-24pt)
rendered in Unreal Engine 5. It predicts a 24-point anatomical keypoint schema
(wheels, head/tail lights, exhaust, roof corners, center, mirrors, bumper and
window corners) plus a bounding box per vehicle.

[Capture explorer](https://kiselyovd.github.io/ue5-vehicle-synth/showcase/) · [Transfer evaluation](https://kiselyovd.github.io/vehicle-keypoints/phase0/synthetic-pretraining/) · [Live real-data 14-point detector](https://huggingface.co/spaces/kiselyovd/vehicle-keypoints-demo)

The live demo uses the separate main model trained on real data, not these synthetic-only weights.

Generated by [kiselyovd/ue5-vehicle-synth](https://github.com/kiselyovd/ue5-vehicle-synth).

## What this model is for

This is a **research / proof-of-concept** model that demonstrates the synthetic
dataset is learnable: a model trained only on it localises vehicles and
their keypoints well on held-out synthetic frames. For real-world 14-point vehicle
keypoints, see the real-image research detector
[kiselyovd/vehicle-keypoints](https://huggingface.co/kiselyovd/vehicle-keypoints).

The training labels are derived geometrically from each vehicle's own mesh data (skeletal wheel bones, vertex-cloud roofline, light/mirror material sections), so keypoints are exact per body shape - a van's high tail lights, a pickup's cab-only roof - not a scaled sedan template.

### Training split and published partitions

The training description reports a 90/10 split of 2,510 frames, with 2,259 used for training. The current Hub dataset publishes train/validation/test partitions of **1,996/257/257** frames. These are different split descriptions; their correspondence is not documented. The Hub test partition has not been established as an independent evaluation set for the existing synthetic-only weights. The recorded in-domain results below refer to the training run's validation description, not automatically to the current Hub test.

## Recorded in-domain results (training-run validation)

| Metric | Box | Pose |
|---|---|---|
| mAP@50 | **0.840** | 0.602 |
| mAP@50-95 | 0.629 | 0.390 |

Pose mAP depends on the run's OKS configuration. A human-pose default does not establish that the reported vehicle result is systematically understated. Trained from
`yolo26n-pose` on 2,259 synthetic frames (the mesh-derived 2,510-frame capture,
90/10 split), 100 epochs, imgsz 480.

## Usage

```python
from huggingface_hub import hf_hub_download
from ultralytics import YOLO

w = hf_hub_download("kiselyovd/citysample-vehicle-keypoints-24pt", "best.pt",
    revision="72a89c4eeb57ad652be02e65fef174838da262d6", token=False)
model = YOLO(w)
results = model.predict("your_street_scene.jpg", device="cpu", imgsz=480, conf=0.25)
# results[0].keypoints.xy -> (N, 24, 2) keypoints per detected vehicle
```

## Honest caveats

- **Synthetic domain.** Trained only on rendered frames; the sim-to-real gap is real and measured: on the CarFusion test set this model reaches PCK@0.05 ~0.14 (first 14 points) - it learns vehicle topology but localisation on real photos is unreliable. The reported controls did not resolve the transfer gap; these artifacts do not isolate appearance, fleet coverage and label quality as causal contributions.
- **Fleet coverage.** City Sample has on the order of a dozen vehicle models; coverage of unfamiliar real vehicle shapes requires separate evaluation. See the [sim-to-real study](https://kiselyovd.github.io/vehicle-keypoints/phase0/synthetic-pretraining/) for the full analysis.
